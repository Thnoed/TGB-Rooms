# AI Agent Guide: Embedding `tgb-rooms` into a Telegram Bot

> Audience: an AI coding agent performing an integration task.
> Language of this document: English. Source code, docstrings and the
> developer README are in Russian.
>
> `tgb-rooms` is a standalone, framework-level room system extracted from
> `shelter-tgbot`. **Do not modify `shelter-tgbot` when integrating** — copy the
> `tgb_rooms/` package into the target bot (or put its parent directory on
> `PYTHONPATH`) and wire it up as described below. Nothing in this package
> imports `app.*`, `shelter-core`, a database, or a WebSocket client.

---

## 0. What the library gives you (do not reimplement these)

- Room creation wizard: **name → type (private/open) → password** (password
  asked only for private rooms). A room key is generated by the backend.
- Joining by key (`/join <CODE>`), with password prompt for private rooms and
  a blacklist check on entry.
- Browsable list of **active joinable rooms** with pagination
  (prev/next, jump to page by number, pick-a-room button, back).
- Built-in per-room **blacklist**: view, add (kick), remove (pardon),
  `/kick <nick>`, `/pardon <nick>`, owner + `waiting`-status guards.
- Persistent **main room message** with info (name, key, privacy, status,
  members with 👑/🤖/🚪 marks, settings summary) and buttons (leave,
  blacklist, custom, settings). Auto-refreshed for every member.
- Leave / disband (`/leave`, `/disband` + `/confirm <CODE>`).
- Hooks and public APIs for external events (WebSocket, game, admin panel).
- Two backends: `MemoryRoomsBackend` (zero external services) and
  `RestRoomsBackend` (adaptable to any REST API).

Everything else — game settings, themes, bots, your main menu, user
registration, i18n engine, persistence, WebSocket — is a **customization
point**, not library code.

### Import-only rule + public contract

Integrate **through imports only** — write code in the host project, never
edit `tgb_rooms/` for standard tasks (custom steps, buttons, settings,
texts, hooks, backends all plug in via `RoomsConfig`). Everything listed in
`tgb_rooms.__all__` (see `tgb_rooms/__init__.py`) is stable: names,
signatures and behavior are preserved between minor versions. New
`RoomsConfig` fields are always optional; defaults always mean "behave like
the original bot".

Stable entry points you will use most:

```python
from tgb_rooms import (
    Rooms, RoomsConfig, Hooks,              # facade + configuration
    MemoryRoomsBackend, RestRoomsBackend, RestEndpoints,  # backends
    RoomsStorage, InMemoryRoomsStorage,     # bindings (override for DB)
    Room, Member, RoomDraft, RoomResult, Principal, Identity, UserBinding,
    CreateRoom, JoinRoom, RoomsBrowser,     # FSM states (host routers can filter on them)
    LobbyButton, SettingsExtension, SettingsContext,
    TextCreateStep, ChoiceCreateStep, MaxPlayersStep, StepOutcome,
    DefaultTexts, format_lobby_message, format_blacklist_message,
)
```

If the task does not fit these extension points (truly custom flow), you may
open the internals — they are split into small files on purpose (see §7).
Read only the section you need, keep behavior-compatible changes, and run
`python -m pytest tests/ -q` from `tgb-rooms/` afterwards.

## 1. Pre-flight checklist (answer these before writing code)

Collect from the developer or infer from the target repository:

1. **aiogram version** — must be `aiogram>=3.13,<4`. The target bot must use
   `Dispatcher(storage=...)` (FSM storage is required).
2. **Backend**:
   - In-process / prototype / no server → `MemoryRoomsBackend` (default).
   - Existing HTTP API → `RestRoomsBackend` + `RestEndpoints` + `room_parser`.
   - Existing database/service layer → subclass `RoomsBackend`.
3. **Identity**: does the bot already have its own user model, player ids,
   or API tokens? If yes, implement `identity_resolver` returning `Identity`.
4. **Language**: how does the bot resolve a user's language? Implement
   `language_resolver` or set `default_language`.
5. **Main menu**: the library does not own it. Decide between
   `RoomsConfig.on_show_menu` (recommended) and embedding
   `rooms.entry_keyboard(lang)` into the host's `/start` handler.
6. **Settings**: does the target bot need a "room settings" screen? If yes,
   implement `SettingsExtension` (see Step 9). By default there is none.
7. **Extra lobby buttons**: start game, bots, chat, etc. → `LobbyButton`.
8. **Conflicts**: which commands and callback prefixes already exist in the
   bot? Override `RoomsConfig.commands` and `callback_prefix` accordingly.
9. **Parse mode**: library texts are HTML by default. If the bot uses
   Markdown, set `parse_mode` and supply compatible texts.
10. **External events**: does a WebSocket/game layer need to refresh lobbies
    or clear bindings? Plan calls to `refresh_lobbies` /
    `notify_room_changed` / `on_room_deleted`.

## 2. Integration steps (in order)

### Step 1 — Install the package

Copy the whole `tgb_rooms/` directory next to the bot's modules, or add the
`tgb-rooms` root to `sys.path` / `PYTHONPATH`. There is no `pyproject.toml`
and no packaging metadata by design: this is a source-level drop-in module.

Dependencies:

```
aiogram>=3.13,<4          # required
aiohttp>=3.9              # only if RestRoomsBackend is used (lazy import)
```

Sanity check after copying:

```bash
python -c "import tgb_rooms; print(tgb_rooms.__version__)"
```

### Step 2 — Create one `Rooms` instance at startup

```python
from tgb_rooms import Rooms, RoomsConfig, MemoryRoomsBackend

rooms = Rooms(
    backend=MemoryRoomsBackend(),
    config=RoomsConfig(default_language="ru"),
    bot=bot,                  # or call rooms.attach_bot(bot) later
)
```

`Rooms` holds the backend, the binding storage, texts, keyboards, UI helpers,
extensions and hooks. Keep it as a singleton for the lifetime of the bot.

### Step 3 — Attach the bot and include the router

```python
from aiogram import Dispatcher
from aiogram.fsm.storage.memory import MemoryStorage

dp = Dispatcher(storage=MemoryStorage())
dp.include_router(host_router)          # host's own handlers first
dp.include_router(rooms.build_router()) # BEFORE any catch-all/fallback handler
```

Rules:

- `build_router()` must be called once; store the returned `Router`.
- Include it **before** the host's fallback / `StateFilter(None)` handlers,
  otherwise unknown messages may swallow the library's FSM input.
- Aiogram checks a parent router's own handlers before its child routers, so
  `SettingsExtension.build_router()` / `extra_routers` handlers run after the
  library's own handlers.
- `dp` must have an FSM storage (`MemoryStorage`, Redis, ...).
- `rooms.attach_bot(bot)` is also done automatically by a small router-level
  middleware, but calling it explicitly is safer for background refreshes.

### Step 4 — Wire the main menu

Two supported patterns (pick exactly one):

**A. Host owns `/start`, library buttons are embedded** (simplest):

```python
from aiogram.filters import CommandStart

@host_router.message(CommandStart())
async def cmd_start(message):
    await message.answer(
        "<b>Main menu</b>",
        reply_markup=rooms.entry_keyboard("ru"),
    )
```

**B. Library shows a menu after cancel/leave/room deletion**:

```python
async def show_menu(bot, chat_id, principal, rooms):
    await bot.send_message(
        chat_id,
        "<b>Main menu</b>",
        reply_markup=rooms.entry_keyboard(principal.language),
    )

config = RoomsConfig(on_show_menu=show_menu)
```

If `on_show_menu` is `None`, the library shows a minimal built-in menu with
the entry keyboard (`MENU_TITLE` text). Override it to match the host UI.

### Step 5 — Identity and language

Default: `player_id = str(telegram_id)`, `display_name = full_name`,
`token = None`, `language = default_language`.

```python
from tgb_rooms import Identity

def identity_resolver(event, data):
    tg_user = data["event_from_user"]
    user = db.get(tg_user.id)                    # host's user model
    return Identity(
        user_id=tg_user.id,
        player_id=user.player_id,                # id known to RoomsBackend
        display_name=user.nick or tg_user.full_name,
        token=user.api_token,                    # REQUIRED for RestRoomsBackend
        language=user.language,
        extra={"role": user.role},
    )

config = RoomsConfig(
    identity_resolver=identity_resolver,
    language_resolver=lambda user_id, data: db.get(user_id).language,
)
```

`identity_resolver` receives the aiogram event and the **full dispatcher
context dict** (all DI keys of the host are available). It may be sync or
async. The resulting `Principal` is passed to every hook, renderer, button
handler and backend call.

> Important: the blacklist stores `Principal.player_id`, not the Telegram id.
> If the host uses a different identity scheme, keep it consistent in the
> backend.

### Step 6 — Texts

```python
config = RoomsConfig(
    default_language="ru",
    text_overrides={"ru": {"CREATE_NAME_PROMPT": "Name your room:"}},
    # or:
    # texts = lambda lang, key, **kw: my_i18n.translate(lang, key, **kw)
    # texts = MyTextProvider()   # .get/.table/.status_title
    parse_mode="HTML",
)
```

Keep `{placeholders}` when translating. Keys live in `tgb_rooms/texts.py`
(`_RU`, `_EN`, `ERROR_TEXT_KEYS`, `EVENT_TEXT_KEYS`). Unknown keys fall back
to the default language, then to the key itself.

### Step 7 — Customize the creation wizard

Default flow is exactly `name → privacy → password`. To append steps:

```python
from tgb_rooms import MaxPlayersStep, ChoiceCreateStep, TextCreateStep

config = RoomsConfig(create_steps=[
    MaxPlayersStep(lo=2, hi=12),   # ready-made example (writes draft.max_players)
    ChoiceCreateStep(
        key="mode",
        prompt_key="CREATE_PRIVACY_PROMPT",   # replace with your own text key
        choices_list=[("classic", "Classic"), ("fast", "Fast")],
        apply_field="mode",                   # -> draft.settings["mode"]
    ),
])
```

`CreateStep` contract: `key`, `mode` (`"text"` or `"choice"`),
`prompt(texts, lang)`, `choices(texts, lang)`, `validate(raw, principal,
texts, lang) -> StepOutcome`, `apply(draft, value)`. `TextCreateStep` and
`ChoiceCreateStep` cover most cases; subclass for custom validation.
`RoomDraft` fields: `name`, `is_private`, `password`, `max_players`,
`settings`, `extra`. Custom values land in `settings`/`extra` and are handed
to `RoomsBackend.create_room`.

### Step 8 — Customize the lobby

```python
from tgb_rooms import LobbyButton

async def on_start(callback, room, principal, rooms):
    await game.start(room.code)
    await callback.answer("Game started")

config = RoomsConfig(
    extra_lobby_buttons=[
        LobbyButton(
            text="▶️ Start game",
            visible=lambda room, p: room.is_owner(p.player_id),
            handler=on_start,       # async (callback, room, principal, rooms)
        ),
    ],
    room_info_renderer=None,        # or: async (room, principal, rooms, lang) -> str
    settings_summary=None,          # or: async (room, principal, rooms) -> list[str]
    can_manage=None,                # or: (room, principal) -> bool
    needs_leave_confirm=None,       # or: (room, principal) -> bool
)
```

The library generates a unique `ExtraCB(index=i)` callback and registers the
handler itself. Keep the list order stable: indices are positional.

### Step 9 — Implement `SettingsExtension` (if needed)

The library only adds a "Settings" button and calls `open(ctx)`; the screen,
keyboard, FSM states and callbacks belong to the host.

```python
from aiogram import Router
from aiogram.types import InlineKeyboardButton, InlineKeyboardMarkup
from tgb_rooms import SettingsContext

class GameSettings:
    def button_text(self, room, principal, texts, lang):
        return texts.get(lang, "SETTINGS") if room.is_owner(principal.player_id) else None
        # return None -> no button at all

    def is_available(self, room, principal):
        return room.is_owner(principal.player_id) and room.status == "waiting"

    async def open(self, ctx: SettingsContext):
        kb = InlineKeyboardMarkup(inline_keyboard=[
            [InlineKeyboardButton(text="Change password", callback_data="gset:pwd")],
            [InlineKeyboardButton(text="⬅️ Back", callback_data=ctx.close_callback())],
        ])
        await ctx.rooms.ui.send(
            ctx.bot, ctx.chat_id, "⚙️ Room settings", reply_markup=kb
        )

    def build_router(self, rooms) -> Router:
        r = Router()
        # register your own callback/FSM handlers here; use rooms.get_room(...)
        # and rooms.backend.update_settings(...) / set_password(...)
        return r

config = RoomsConfig(settings_extension=GameSettings())
```

Useful `SettingsContext` members: `bot`, `chat_id`, `message_id`, `room`,
`principal`, `lang`, `rooms`, `close_callback()` (packed `callback_data` for
the built-in "close settings" handler), `close()` (re-render the lobby).
Use `ctx.rooms.settings_close_callback()` if you build the keyboard elsewhere.

`extra_routers=[...]` is an alternative: include any host `Router` inside the
library router without implementing `SettingsExtension`.

### Step 10 — Choose / implement the backend

**Memory (default)**: `MemoryRoomsBackend(code_length=6, code_factory=None,
joinable_statuses={"waiting"}, default_status="waiting")`. Supports
`update_settings`, `set_password`, `set_status`, owner transfer on leave.

**REST**:

```python
from tgb_rooms import RestRoomsBackend, RestEndpoints

backend = RestRoomsBackend(
    "https://api.example.com/v1",
    endpoints=RestEndpoints(
        create="/rooms",
        join="/rooms/{code}/join",
        state="/rooms/{code}/state",
        list="/rooms?limit={limit}&offset={offset}",
        blacklist="/rooms/{code}/blacklist",
        kick="/rooms/{code}/kick",
        pardon="/rooms/{code}/pardon",
    ),
    room_parser=lambda raw: my_room_from_api(raw),  # optional
    headers_factory=lambda principal: {"X-User": principal.player_id},
    timeout=10.0, retries=2,
)
```

Expected error shape: `{"error": true, "code": "...", "message": "..."}`.
Expected list shape: `{"items": [...], "total": N}`. Expected state shape:
`{"code", "name", "owner_id", "is_private", "status", "max_players",
"players": [{"player_id", "display_name", "is_bot", "state"}]}`.
`room_parser` overrides `_parse_room` when the API differs.

**Custom**: subclass `RoomsBackend` and implement all abstract methods;
return `RoomResult.success(room, **data)` / `RoomResult.fail(code, message,
**data)`. Error codes should match `ERROR_TEXT_KEYS` (`room_full`,
`room_access_denied`, `already_in_room`, ...). For `join_room`, set
`data["blacklisted"]=True` or `data["password_required"]=True` on
`room_access_denied` so the UI reacts correctly.

For persistence across restarts, also implement `RoomsStorage` (adapter over
the host DB) and pass `storage=...` to `Rooms`.

### Step 11 — Wire external events (WebSocket / game / admin)

```python
# after any change to members/status/settings:
await rooms.refresh_lobbies(code)

# generic event: hooks + optional per-user notices + refresh
await rooms.notify_room_changed(code, "player_joined", name="Anna")
await rooms.notify_room_changed(code, "settings_updated", refresh=True, notify=False)

# room physically gone on the server: clear bindings, notify, show menu
await rooms.on_room_deleted(code, reason="ws")
```

Event names mapped to hooks: `player_joined`, `player_left`,
`player_kicked`, `owner_changed`, `room_deleted`, `blacklist_changed`,
`settings_updated`; every event also fires `on_room_changed`. Set
`notify_events=True` (or pass `notify=True`) and `event_text_keys` to send
localized transient notices to members.

### Step 12 — Hooks

```python
from tgb_rooms import Hooks

async def on_created(*, rooms, principal, room, **payload):
    await analytics.track("room_created", room.code)

config = RoomsConfig(hooks=Hooks(
    on_room_created=on_created,
    on_room_joined=None, on_room_left=None, on_room_disbanded=None,
    on_room_deleted=None, on_room_changed=None,
    on_member_joined=None, on_member_left=None, on_member_kicked=None,
    on_member_pardoned=None, on_owner_changed=None,
    on_blacklist_changed=None, on_settings_changed=None, on_error=None,
))
```

Hook signature: `async def hook(*, rooms, principal, room, **payload)` —
sync hooks are also accepted. `principal`/`room` may be `None` for external
events. Hook exceptions are logged and never break a handler; `on_error` is
then invoked.

## 3. Usage examples (copy-paste recipes)

All recipes import from `tgb_rooms` only — no edits inside the package.

### A. Minimal bot (memory backend, default flows)

```python
import asyncio, os
from aiogram import Bot, Dispatcher, Router
from aiogram.client.default import DefaultBotProperties
from aiogram.enums import ParseMode
from aiogram.filters import CommandStart
from aiogram.fsm.storage.memory import MemoryStorage
from tgb_rooms import Rooms, RoomsConfig, MemoryRoomsBackend

async def main():
    bot = Bot(os.environ["TG_BOT_TOKEN"],
              default=DefaultBotProperties(parse_mode=ParseMode.HTML))
    dp = Dispatcher(storage=MemoryStorage())

    rooms = Rooms(backend=MemoryRoomsBackend(),
                  config=RoomsConfig(default_language="ru"), bot=bot)

    host = Router()
    @host.message(CommandStart())
    async def start(message):
        await message.answer("<b>Main menu</b>",
                             reply_markup=rooms.entry_keyboard("ru"))
    dp.include_router(host)
    dp.include_router(rooms.build_router())
    await dp.start_polling(bot)

asyncio.run(main())
```

## 4. Conflict resolution reference

| Problem | Fix |
|---|---|
| Host already uses `/create`, `/join`, ... | `RoomsConfig(commands={...})` — full dict of lists |
| Host uses `tgr...` callbacks | `RoomsConfig(callback_prefix="myrooms")` |
| Host has its own "Cancel" text | `RoomsConfig(cancel_texts=frozenset({...}))` |
| Host uses Markdown | `parse_mode` + own texts (library default is HTML) |
| Host does not want its menu message deleted | `delete_menu_on_action=False` |
| Host wants a different owner/status rule | `can_manage`, `editable_statuses`, `joinable_statuses` |
| Host has a catch-all handler | include `rooms.build_router()` **before** it |
| Host needs FSM states for settings | `SettingsExtension.build_router()` / `extra_routers` |
| Host needs `player_id`/token mapping | `identity_resolver` returning `Identity` |
| Host needs persistent bindings | custom `RoomsStorage` implementation |

## 5. Verification checklist (do this before reporting success)

1. `python -c "import tgb_rooms"` succeeds; `rooms.build_router()` returns a
   `Router` with **15 message** and **22 callback** handlers (plus any
   extension routers).
2. `/start` shows the entry keyboard; all three buttons open the right flow.
3. Create: name → privacy (open and private) → password (only for private) →
   any custom steps → room key appears in the main message.
4. Second user joins by `/join <CODE>`; private room asks for a password;
   wrong password is rejected, correct one succeeds.
5. `/rooms` lists open waiting rooms; prev/next, page-number input and
   "pick" all work; joining from the list works.
6. Owner opens the blacklist, kicks a member, the member can no longer join;
   `/pardon <nick>` or the "Remove" button restores access; `/kick` and
   `/pardon` commands work; non-owners are denied.
7. Other members' main messages refresh after join/leave/kick.
8. `/leave` returns to the host menu; `/disband` + `/confirm <CODE>` clears
   the room and notifies everyone.
9. Cancel (`Отмена` / `Cancel` / `/cancel`) aborts any dialog; the reply
   keyboard is removed.
10. If a WebSocket/game layer exists, verify `refresh_lobbies`,
    `notify_room_changed` and `on_room_deleted` are called on the relevant
    events.

## 6. Common mistakes

- Forgetting `Dispatcher(storage=...)` → no `FSMContext`, dialogs break.
- Including `rooms.build_router()` after a fallback handler → FSM input is
  swallowed.
- Forgetting `rooms.attach_bot(bot)` when only background refreshes are used
  (it is auto-attached for normal updates, but explicit is safer).
- Using `RestRoomsBackend` without putting the API token into
  `Identity.token` → 401/403 from the server.
- Assuming the blacklist stores Telegram ids — it stores `player_id`.
- Expecting a settings screen by default — there is none; implement
  `SettingsExtension`.
- Editing `tgb_rooms/handlers/_*.py` to add project logic — use
  `extra_lobby_buttons`, `settings_extension`, `create_steps`, `extra_routers`
  and `Hooks` instead. The package must stay project-agnostic. Open the
  internals only for behavior changes the public API cannot express, then run
  `python -m pytest tests/ -q` from `tgb-rooms/`.
- Modifying `shelter-tgbot` during integration — it is the source project, not
  the target.
